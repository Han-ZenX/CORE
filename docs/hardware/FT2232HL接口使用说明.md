# FT2232HL 接口使用说明

本文说明 FT2232HL 在 CORE 板上作为调试桥的用法：双通道如何分配、JTAG 与 UART 如何共存、主机端如何识别、配置 EEPROM 如何接线与量产烧录。

> 适用范围：FT2232HL（LQFP-64），配置 EEPROM 为 93LC56BT-I/OT。文中 `x` 代表通道字母，A 通道引脚为 `ADBUS/ACBUS`，B 通道为 `BDBUS/BCBUS`。

---

## 0. 总览

@fig:ft_arch 图 1　双通道架构与主机端枚举关系

FT2232HL 是一颗 **USB 复合设备**：一个 USB 口、一组 VID:PID（默认 `0403:6010`），下挂 **两个完全独立的 USB Interface**，各驱动一个通道引擎。

这带来本文最重要的一个结论：

**JTAG 和 UART 不需要"切换"，让 Channel A 跑 JTAG、Channel B 跑 UART，两者同时在线。**

绝大多数商用调试器（FT2232H Mini Module、Digilent HS2、Olimex ARM-USB-OCD）都是这个方案。只有在引脚实在不够、被迫让一个通道兼两职时，才会遇到切换问题（见第 4 节）。

---

## 1. 支持的全部通讯模式

每个通道可独立配置为下列任一模式：

| 模式 | 可用通道 | 最高速率 | 用途 |
| --- | --- | --- | --- |
| UART / RS232 | A、B | 12 Mbaud | 串口，带 RTS/CTS、DTR/DSR 硬件流控 |
| MPSSE 之 JTAG | A、B | 30 MHz | 芯片调试 |
| MPSSE 之 SPI | A、B | 30 MHz | **仅 Master**，支持模式 0/1/2/3 |
| MPSSE 之 I2C | A、B | 约 400 kHz | 软件模拟，有硬件前提，见第 6 节 |
| 异步 Bit-Bang | A、B | 约 1 MB/s | 8 位 GPIO 直接读写 |
| 同步 Bit-Bang | A、B | — | 时钟驱动的 GPIO |
| 异步 245 FIFO | A、B | 8 MB/s | 8 位并口 |
| 同步 245 FIFO | **仅 A** | 40 MB/s | FPGA 高速数据流 |
| CPU-FIFO（同步/异步） | A、B | — | 模拟 CPU 总线，带地址线 |
| Fast Opto-Isolated Serial | A、B | — | 光隔离串行 |

### 1.1 一条硬限制

**同步 245 FIFO 会让整颗芯片进入单通道状态**，启用后 Channel B 完全不可用。

如果需要"40 MB/s 高速口 + 独立串口"的组合，FT2232HL 做不到，应改用 FT600/FT601，或另加一颗 FT232。

### 1.2 不支持的

- **SPI Slave**：只能做主机
- **CAN / LIN 协议层**：RS485 可外挂收发器，用 RTS 或 TXDEN 引脚控方向
- **USB Host**：本芯片只能作为 USB device
- **硬件 I2C 控制器**：I2C 是 MPSSE 模拟出来的

## 2. 推荐的通道分配

| 方案 | Channel A | Channel B | 说明 |
| --- | --- | --- | --- |
| **调试板标配** | MPSSE 之 JTAG | UART | 最常用，两者同时可用 |
| **带 Flash 烧录** | MPSSE（JTAG / SPI 运行时切） | UART | 用 `flashrom` 直烧板载 SPI Flash，省一个编程器 |

第二种方案之所以成立，是因为 **JTAG 与 SPI 的引脚天然对应**：TCK 即 SCK、TDI 即 MOSI、TDO 即 MISO，硬件走线不用动，只有片选 CS# 需要单独安排（占用 TMS 那根线，或改用某个 GPIOL 引脚）。

`flashrom` 原生支持本芯片作 SPI 编程器：

```
flashrom -p ft2232_spi:type=2232H,port=A -w firmware.bin
```

## 3. 引脚复用对照

@fig:ft_pinmux 图 2　同一组数据引脚在四种模式下的功能

图 2 中红框标出的 **xD0 至 xD3 是复用冲突区**。这四根线在不同模式下含义完全不同，所以同一通道换模式时，**外部走线也必须跟着换**，否则会出现 JTAG 的 TCK 直接怼到目标板串口 RX 上这类硬件冲突。

xD4 至 xD7 与 xCBUS0 至 xCBUS7 在 MPSSE 下恒为通用 GPIO（GPIOL0-3 / GPIOH0-7），可自由用作复位、片选、LED 指示等。

## 4. 同一通道内切换模式

**只在被迫共用一个通道时才需要这一节。** 优先用第 2 节的分通道方案。

### 4.1 MPSSE 不是 EEPROM 选项

这是最容易误解的一点：**EEPROM 里只能选 `RS232 UART` 或 `245 FIFO`，没有 MPSSE 这个选项。**

MPSSE 是**运行时**通过 D2XX 命令进入的：

```c
FT_SetBitMode(h, 0x00, FT_BITMODE_RESET);   // 0x00 -> back to UART
FT_SetBitMode(h, 0x00, FT_BITMODE_MPSSE);   // 0x02 -> enter MPSSE (JTAG/SPI/I2C)
```

完整流程：关闭串口应用 → `FT_Open` → `FT_SetBitMode(MPSSE)` → 执行 JTAG 操作 → 用完 `FT_BITMODE_RESET` 退回 UART。

### 4.2 驱动占用问题

同一个通道不能同时被 VCP 和 D2XX 打开，这是切换时最常卡住的地方。

**Windows**：VCP 驱动把通道枚举成 COM 口后，D2XX 抢不到。用 FT_PROG 把该通道的 Driver 从 `Virtual COM Port` 改成 `D2XX Direct`，重新插拔生效。

**Linux**：`ftdi_sio` 会自动绑定，OpenOCD 打不开。先解绑：

```
echo -n "1-1.2:1.0" | sudo tee /sys/bus/usb/drivers/ftdi_sio/unbind
```

其中 `:1.0` 是 Channel A，`:1.1` 是 Channel B，具体总线编号用 `lsusb -t` 查。

按第 8 节的建议把 A 通道 EEPROM 配成 D2XX，这一步就可以省掉。

## 5. 主机端如何识别 JTAG 与 UART

### 5.1 Type-C 接口本身不参与识别

Type-C 只是 USB 的物理载体。CC 引脚负责插入检测、正反插方向、供电能力广播（Rp/Rd）以及 DP/TBT 这类 Alt Mode 协商，**没有"这个口是 JTAG 还是 UART"的语义**，也不该有 —— 正反插必须功能一致。

板子作为纯 UFP 时，CC1/CC2 各接一个 **5.1 kΩ 下拉到 GND** 即可。不要试图用 CC 状态去切 JTAG/UART，那是滥用协议。

### 5.2 识别发生在 USB 枚举层

| 项目 | Channel A | Channel B |
| --- | --- | --- |
| USB Interface | `0` | `1` |
| 默认描述符 | `Dual RS232-HS A` | `Dual RS232-HS B` |
| Linux 设备节点 | `/dev/ttyUSB0` | `/dev/ttyUSB1` |
| Linux 稳定路径 | `/dev/serial/by-id/...-if00-port0` | `...-if01-port0` |
| Windows | `USB Serial Converter A` | `USB Serial Converter B` |

**枚举顺序是固定的**，A 恒为 Interface 0，不会因插拔顺序改变。

生产上不要依赖 `ttyUSB0` 这种会随插拔顺序变化的名字，用 `by-id` 路径或序列号定位。

### 5.3 让设备自我标识

按第 8 节配置后，OpenOCD 可以精确锁定目标：

```
ftdi vid_pid 0x0403 0x6010
ftdi device_desc "CORE Debug A"
ftdi serial "CORE001"
ftdi channel 0
```

`ftdi channel` 的取值：`0` 为 Channel A，`1` 为 Channel B。

## 6. I2C 的两个硬件前提

@fig:ft_i2c 图 3　MPSSE 做 I2C 时的外部接线要求

MPSSE 的 I2C 是模拟出来的，必须满足两个外部条件，否则完全不工作：

1. **xD1 与 xD2 必须外部短接成一根 SDA。** MPSSE 的输入与输出引脚物理分离，不短接就读不到从机的 ACK。
2. **SCL 与 SDA 都要外接 2.2 kΩ 至 4.7 kΩ 上拉。** MPSSE 引脚不是真开漏，靠固件把引脚切成输入态来模拟高阻态，没有上拉就没有高电平。

结论：**I2C 能用但别扭**。做产线烧录 EEPROM、读配置芯片够用；做高速传感器采集不合适，速率上限约 400 kHz。

## 7. 配置 EEPROM 的接线

@fig:ft_eeprom 图 4　93LC56B 接法与救砖测试点

| FT2232H | 93LC56B | 备注 |
| --- | --- | --- |
| EECS | CS | 直连 |
| EECLK | CLK | 直连 |
| EEDATA | DI | 直连 |
| EEDATA | DO | **必须串 2.2 kΩ** |

**2.2 kΩ 不能省。** FT2232H 把 DI 与 DO 合并到一根 EEDATA 线上，靠这个电阻避免双向驱动冲突。FTDI 官方参考设计（FT2232H 数据手册典型应用电路、AN_113）即为此接法。

### 7.1 选型注意

- **必须用 B 版**。`93LC56B` 是固定 128 x 16（x16 组织），FT2232H 只认这种；`93LC56A` 是 x8 组织，**不能用**。
- SOT-23-6（后缀 `OT`）封装的 ORG 引脚不引出，内部固定为 x16，正合适。
- 引脚编号请对照 Microchip 数据手册的 OT 封装图确认，**不要照搬 SOIC-8 的顺序**。
- 工作电压 2.5 V 至 5.5 V，与 FT2232H 的 3.3 V EEPROM 接口兼容。

### 7.2 留一个救砖测试点

**布板时给 EEPROM 的 CS 引脚留一个测试点。** 一旦写错 VID/PID 导致设备无法枚举，把 CS（或 DO）临时短接到 GND，FT2232H 读不到有效 EEPROM 就会回退片内默认值重新枚举；此时松开短接，用 FT_PROG 的 `Erase` 擦掉重烧即可。

有这个测试点，能省掉一次返修。

## 8. 出厂配置与量产烧录

### 8.1 先澄清一个概念

**FT_PROG 是运行在 PC 上的 Windows 上位机软件，不是芯片里的东西。** 它通过 USB 与 FT2232H 通信，由 FT2232H 代为读写旁边的 EEPROM。

**93LC56BT-I/OT 出厂是空白的（全 `0xFF`）**，不含任何 FTDI 配置数据，Microchip 出厂只做电性测试。

### 8.2 空白 EEPROM 时的行为

芯片检测到 EEPROM 空白（或根本没挂 EEPROM）时，会回退到片内固化默认值，**照样能枚举**：

| 项目 | 空白 EEPROM 时的默认值 |
| --- | --- |
| VID:PID | `0403:6010` |
| Product Description | `Dual RS232-HS` |
| Serial Number | **无**，所有板子都一样 |
| Channel A / B 模式 | 都是 UART + VCP |

所以首件焊好后直接插 USB 就能被 FT_PROG 认到并烧录，**不需要预烧 EEPROM**。代价是没有序列号、没有自定义描述符、JTAG 通道会被 VCP 驱动抢走。

### 8.3 CORE 板建议配置

| 配置项 | 值 | 理由 |
| --- | --- | --- |
| VID:PID | 保持 `0403:6010` | 省掉自签驱动的麻烦 |
| Product Description | `CORE Debug` | 设备管理器里一眼可辨 |
| Serial Number | `CORE` + 自动递增 | 多板同插时可区分 |
| Channel A Driver | **D2XX Direct** | JTAG 通道，不产生 COM 口 |
| Channel B Driver | **Virtual COM Port** | UART 通道，产生 COM 口 |
| Channel A / B Hardware | 都填 `RS232 UART` | MPSSE 是运行时切的，EEPROM 无此选项 |

这样配置后，**系统里只有一个 COM 口，那必然是 UART**，零歧义；`ftdi_sio` 也不会去抢 JTAG 通道，第 4.2 节的解绑操作可以省掉。

### 8.4 小批量烧录

1. 拿第一块板在 FT_PROG 里配好所有选项
2. `File` → `Save As Template`，存成 `.xml`
3. 后续板子：`Devices` → `Scan and Parse` → 载入模板 → `Program`

**务必开启序列号自动递增**：在 `USB String Descriptors` 里勾选 `Auto Generate Serial No.`，设好 Prefix（如 `CORE`），每次 Program 自动加一。没有唯一序列号的话，两块板同时插上就分不清了。

FT_PROG 支持一次扫描多个已连接设备并批量 Program，接 USB Hub 可以同时烧一排。

### 8.5 产线脚本化

| 方案 | 平台 | 说明 |
| --- | --- | --- |
| `ftdi_eeprom`（libftdi） | Linux | 配置文件驱动，最容易接入产线脚本，推荐 |
| D2XX `FT_EEPROM_Program` | 跨平台 | 自写烧录程序，可对接 MES 或序列号数据库 |
| FT_PROG 命令行 | Windows | 3.x 版本带 CLI，参数见软件内 Help |

## 9. 检查清单

投板前逐项确认：

- Channel A 与 Channel B 的用途已明确分配，未出现一个通道兼两职
- 若用 I2C：xD1 与 xD2 已外部短接，SCL/SDA 上拉电阻已放置
- EEPROM 的 DO 到 EEDATA 之间已串 2.2 kΩ
- EEPROM 型号是 `93LC56B`（x16），不是 `93LC56A`
- EEPROM CS 引脚已引出测试点
- Type-C 的 CC1/CC2 各有 5.1 kΩ 下拉到 GND
- 未使用同步 245 FIFO 模式，或已接受 Channel B 不可用的代价
